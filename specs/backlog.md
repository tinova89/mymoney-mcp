| — | Primary currency | Planned | Comes before "Manage accounts", which uses it as the default currency for new accounts. Set in server configuration only (no MCP tool, no REST); changing it needs a restart. Each group may have its own; changing one never affects another group. A group with no setting uses the configured default currency, `BRL` when none is configured. A currency is just its ISO 4217 code (no currency entity); any valid code is accepted. Changing it only affects the default for new accounts; existing accounts keep theirs. The API refuses to start when a configured code is not valid ISO 4217 (fail fast). One shared service gives any feature the primary currency of the current group; features never read the configuration directly. Update `glossary.md`, `business-rules.md`, `mcp-tools.md`. |
| — | Manage accounts | Planned | Depends on "Primary currency". MCP tools only (no REST) to add, list, edit and archive the accounts of the current group. Each account gets a type (`Checking` or `CreditCard`) and a currency (any ISO 4217 code). The name is unique within the group, ignoring case, archived accounts included (restore the archived one instead of creating a new one). `Checking` has an opening balance and its date (balance rules arrive with transactions). `CreditCard` has a statement closing day and a due day (1–31) and no opening balance. A day the month does not have becomes the last day of that month (31 → 30 in a 30-day month). A new account without a currency gets the group's primary currency. The system starts with no accounts (001 seeds none), so the migration needs no default type. Edit cannot change type or currency (see next item). Archive is a soft delete and uses the `needsConfirm` flow; an archived account can be restored. Update `glossary.md`, `business-rules.md`, `mcp-tools.md`. |

Decide what happens to type-specific fields (opening balance, closing/due days) and, once transactions exist, to the account's existing transactions and balances. |

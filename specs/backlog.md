| 005 | Primary currency | Planned | Yes | HIGH | — | Gives 006 the default currency for new accounts. Set in server configuration only (no MCP tool, no REST); changing it needs a restart. Each group may have its own; changing one never affects another group. A group with no setting uses the configured default currency, `BRL` when none is configured. A currency is just its ISO 4217 code (no currency entity); any valid code is accepted. Changing it only affects the default for new accounts; existing accounts keep theirs. An invalid default currency stops the API at startup (fail fast); an invalid group currency invalidates only that group, the others keep working. One shared service gives any feature the primary currency of the current group; features never read the configuration directly. Update `glossary.md`, `business-rules.md`, `mcp-tools.md`. |
| 006 | Manage accounts | Planned | Yes | HIGH | 005 | MCP tools only (no REST) to add, list, edit and archive the accounts of the current group. Each account gets a type (`Checking` or `CreditCard`) and a currency (any ISO 4217 code). The name is unique within the group, ignoring case, archived accounts included (restore the archived one instead of creating a new one). `Checking` has an opening balance and its date (balance rules arrive with transactions). `CreditCard` has a statement closing day and a due day (1–31) and no opening balance. A day the month does not have becomes the last day of that month (31 → 30 in a 30-day month). A new account without a currency gets the group's primary currency. The system starts with no accounts (001 seeds none), so the migration needs no default type. Edit cannot change type or currency (see 014). Archive is a soft delete and uses the `needsConfirm` flow; an archived account can be restored. Update `glossary.md`, `business-rules.md`, `mcp-tools.md`. |

| 008 | Manage transactions | Planned | No | HIGH | 006, 007 | MCP tools only (no REST) to add, list, edit and archive the transactions of an account in the current group. Brings the balance rules: a `Checking` balance is its opening balance plus its transactions; a `CreditCard` transaction falls in a statement by the closing day. Open questions: sign or kind for income vs expense; whether the category is required; transfers between accounts (incl. paying a credit card statement); installments (parcelas); list filters (period, account, category). Update `glossary.md`, `business-rules.md`, `mcp-tools.md`. |
